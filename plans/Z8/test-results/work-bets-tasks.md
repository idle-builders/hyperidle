## NEW ISSUES (not in the 28 flags)

1. **Duplicate "My Team" option in BetCreateDialog team select.** The team `<select>` lists `["Select a team…","Nimmly","My Team","My Team"]` — two identical "My Team" entries. Indicates two distinct teams share the same display name (ambiguous/confusing selection). Evidence: `test-dialog-create.mjs` output.
2. **POST /api/bets does NOT return a derived `title`** (returns raw row). Only GET /api/bets/:id derives title. So `onCreated` cannot show a title without a re-fetch. Minor, but reinforces FLAG-1's FE/BE shape mismatch at creation time too. Evidence: SETUP_zeroBet `returnedTitle:"(none)"`.
3. **Kill leaves an "In progress" task running indefinitely.** Concrete reproduction of FLAG-5's real-world impact: the seed bet had a second task "Routine: QA throwaway …" in `In progress` state; after kill the bet is `killed` but that task remains live (no halt). A killed bet with a still-running in_progress task is a coherent product bug, not just stale copy. Evidence: `11-kill-dialog.png` + post-kill API task state unchanged.
4. **WorkBet stat card progress bar renders a FULL green bar at NaN%.** Beyond the "NaN%" text, the bar fill (`width:NaN%` → browser ignores → element default full width) misleadingly shows a zero-task bet as 100% visually complete. Evidence: `03-bet-detail-zerotask.png` (full green bar under "NaN%").
5. **Browser console floods with 404/400 on normal navigation.** Loading any task detail page emits an uncaught `404` for the missing sessions endpoint; adjusting appetite emits a `400`. These are user-triggered on happy paths, not edge cases. Evidence: CONSOLE_ERRORS + NET_FAILURES in results.json.
