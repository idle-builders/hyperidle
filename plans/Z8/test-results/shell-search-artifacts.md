## NEW ISSUES (not in original 25 flags)

1. **`/settings` redirect URL silently drops the `settings=open` query param after consumption.** Final URL is `/conversations` (not `/conversations?settings=open`) — the AppShell strips the param via `replace:true` after opening the overlay (documented AppShell:241-253). The settings overlay DID open correctly (SETTINGS panel visible), so behavior is correct, but a naive URL-equality test fails. Not a bug, but the redirect is indistinguishable from a plain `/conversations` nav in browser history/analytics.

2. **Seed bet `seed-bet-daily-digest` has status `killed`.** Search and the search panel both correctly surface it with a "Killed" chip — but a killed bet appearing as a top search result for "daily"/"internal" (the only work match) is questionable UX. Killed/archived items are not filtered from search results. Worth confirming this is intended (no status filter in search.ts category 2).

3. **No cross-category result cap or interleaving.** With per-category caps of 5 and no global ranking, a query matching many knowledge items but few conversations always shows knowledge below an empty/sparse conversations group — the grouped layout hard-codes Conversations→Work→Knowledge order regardless of match strength. Compounds Flag 4.

4. **Artifact permalink leaks the raw artifact UUID in the top-right** (visible in screenshots, e.g. `02dc0c94-409b-...`). Combined with Flag 25 (no per-user/team boundary on GET /api/artifacts/:id), any authenticated caller can enumerate/read any artifact by id. Low severity in single-tenant, but the id is presented as UI chrome.
