Director's cut · Rev 03

Conversations, reconciled.

Version A is a fresh visual proposal with opinionated information architecture. Version B is the shipping React app in packages/web/src — real components, real data shapes, real keybinds. This document extracts the best from each, resolves the conflicts, and marks every change with exactly which file in Version B it affects.

What we kept, what we changed

From Version B (canonical): the four-zone shell, the threads.ts shape, the five ArtifactKinds in ArtifactView.tsx, the ten verdict actions, the StatusChip color map (including blocked = warning, not error), the ⌘K jump-to contract. From Version A (visual & IA): the section groupings (Pinned / Blocking / Reviews / Chats / Resolved), the proposer-led ReviewHeader, the kind-badge chip, the keyboard-shortcut overlays on verdict buttons. New (agreed on today): the Reasoning block that precedes every artifact, inline comment anchoring in text_diff, and the grouped-message threading in the Chief-of-Staff chat.

Structured comparison

01 · Shell
Four-zone layout
IconRail + Submenu + Main + collapsible Rail. Explicit section groupings in the submenu (Pinned / Blocking / Reviews / Chats / Resolved).
Same 4-zone shell (App.tsx). Submenu groups by status not by kind — mixes a “blocking” chat with a “blocking” review.
Keep B's shell. Adopt A's section ordering — Pinned first, then Blocking (all kinds), then Reviews, then Chats, then Resolved 24h. Blocking outranks kind because attention economy beats taxonomy. Winner · A's IA
02 · Status semantics
What does "blocked" mean?
A read blocked as danger and colored it red — treating it like an error state.
B maps blocked = warning (amber) in StatusChip.tsx. An agent is stuck, not broken.
B wins. Red is reserved for error. Blocked = amber. This is a semantic distinction the existing design system already encodes, and A was wrong to override it. Winner · B
03 · Review header
Who owns the identity row?
Proposer-led: agent avatar + name + role on the left, verdict toolbar on the right, SLA + routing on a second row.
Title-led: the artifact title is the primary anchor, proposer info compressed into a subline.
Keep A's proposer-led identity — in a multi-agent system the “who” is more informative than the “what.” But move the artifact title into the body, above the Reasoning block, where it belongs. Winner · A
04 · Verdicts
Surfacing 10 actions
Three primary buttons: Reject, Request changes, Approve, each with a keybind chip.
Ten actions defined (approve, changes_requested, rejected, pause, resume, delegate, fork, merge, archive, escalate). All flat in a row.
Four surfaced + one overflow. Primary verdicts are Approve / Request changes / Reject (A/R/X). Pause gets its own button when blocking=true. Everything else lives under a ... menu with the keybinds still shown. Winner · hybrid
05 · Reasoning
Do we see how the agent thought?
Absent. The artifact is presented as a fait accompli.
Message.reasoning?: string[] exists in the data but MessageBubble.tsx doesn't render it.
New block. Every review opens with a collapsible Reasoning panel listing the numbered steps from reasoning[]. This is the single biggest leverage point: the reviewer's first question is always “why did you do it this way?” Winner · A, but do more
06 · Artifact kinds
How do the 5 shapes render?
Only text_diff designed in detail. Others sketched.
All 5 wired to data (ArtifactView.tsx) but rendered as minimal stubs — no polish, no inline interaction.
All 5 rendered at fidelity in this doc (Deliverables 02–06). Each adopts a house grid: meta strip at the top, primary content below, related history underneath. Verdict toolbar stays constant regardless of kind. Winner · neither, synthesize
07 · Chat vs review
When is there no verdict?
Chat treated as “a review without the buttons.” Same header shell, empty verdict row.
Chat is a distinct mode in ConversationsReview.tsx — different header, no artifact, messages can reference artifacts.
B wins. Chat is not a review. Different header (agent identity + pin/mute), no verdict toolbar, messages can embed artifact previews inline. Deliverable 07 shows the Chief-of-Staff variant. Winner · B
