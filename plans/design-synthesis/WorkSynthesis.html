Director's cut · Rev 01

Work, reconciled.

Version A is a visual proposal for the Work surface. Version B is the shipping React app in web/src — WorkPortfolio, WorkTeam, WorkBet, plus Canvas, Kanban, PitchSelector and three card components. This document extracts the best from each, resolves the conflicts, and names the file each change lives in.

What we kept, what we changed

From Version B (canonical): Shape Up's two-lane canvas (Shaped / Committed — explicitly not four, per HUMAN_INTERFACE_LAYER §4.3), the four-column Kanban (Planned / Blocked / In Progress / Done), the STATE_TO_COLUMN folding, BET_STATUS_MAP, TASK_STATE_MAP, blocked = warning (not error), keyboard drag (Alt+Arrow), data-droppable-column test hooks, the Tag + StatusChip + KeyValue primitives. From Version A (visual & IA): the morning-check emphasis in Portfolio, cycle management as a first-class surface, progress visualization on BetCards, the PitchSelector as a committed "menu of bets" not a dropdown. New (agreed today): capacity-aware Canvas layout, bet-grouped TaskCard rendering on the Kanban, a pitch detail expansion inside PitchSelector, and a bet detail page that combines pitch body + task table + comment thread.

01 · Portfolio overview
The 15-second morning check
Rich product cards: lead, status, active bets, shipped count, velocity sparkline. Plus a prominent cycle management card.
WorkPortfolio.tsx renders 3 product cards with only name + StatusChip + Active bets + Ship rate. No cycle card, no sparkline, no lead, no shipped count. Thin.
Adopt A's richer card but respect B's card primitive (tonal layering, no borders, KeyValue rows). Cycle management lives on the Portfolio page as a secondary stripe — it's a control, not the hero. Four products (A asked for it) and a sparkline per card. Winner · A's structure
02 · Canvas lanes
Two lanes or four?
A implicitly assumed a four-lane Kanban-style canvas.
Two lanes: Shaped (available pitches) + Committed (bets in progress). Capacity badge "N / C" with "Over capacity" warning in error red. Grounded in Shape Up methodology.
B wins, decisively. Two lanes IS the Shape Up metaphor — the "bet" is the decision to commit capacity. Four lanes would turn it back into a project-management board. Keep capacity visual — make it more prominent. Winner · B
03 · Kanban columns
Which states are columns?
A described 4 columns as "accepted → in_progress → review → done" — conflating review with its own column.
Planned / Blocked / In Progress / Done. STATE_TO_COLUMN folds proposed+accepted → planned, in_progress+review → in_progress, hides hold+killed. Review is a sub-state of in-progress.
B wins. The board shows what needs attention, not every internal state. Review is a label ON an in-progress card, not a column. Blocked is a column because blocked tasks need human intervention. Winner · B
04 · PitchSelector
Overlay or dropdown?
A imagined a small picker — pick a pitch, add to canvas.
Full-width overlay inside the page flow (not a modal), with SearchField, filterable list, multi-select via ✓ marker. Returns to Kanban when closed.
Keep B's overlay list, but do NOT replace the Kanban — inline it between Canvas and Kanban while open. Add an expanded detail pane when one pitch is selected, showing the full pitch body (problem / appetite / solution / rabbit holes) before committing. Winner · B + add detail pane
05 · Bet detail page
From "scan" to "understand"
A proposed a drill-down with pitch body + comments.
WorkBet.tsx shows BetCard header + list of TaskCards. No pitch body, no comments, no breadcrumb. Very thin.
Adopt A's structure: breadcrumb → bet header (enriched) → pitch body (markdown) → task table → comment thread. Tasks shown as a table not stacked cards — denser and sortable on the detail page. Winner · A
06 · BetCard vs TaskCard
Visual weight
Both treated as roughly equal cards.
BetCard is heavier: Tag + StatusChip + Appetite KV + progress bar. TaskCard is lighter: optional betTag + StatusChip + owner + cost. Blocked tasks get a red border.
B wins on density. Bets are 1–6 week commitments; tasks are atomic units. The weight difference signals "these are different kinds of things." Preserve the blocked-border treatment — it's the only place error red appears on TaskCard. Winner · B
07 · State semantics
What does "blocked" look like?
Not distinguished from error.
blocked = badge-warning (amber) per I4 S7. Error is red. Blocked = "stuck waiting, recoverable"; error = "broken, intervention required."
B wins — the same call as the Conversations synthesis. Preserve amber for blocked everywhere. On TaskCard, the red border for state === "blocked" is additive to the amber chip and intentional: the border is a layout signal (scan-the-board), the chip is the semantic signal. Winner · B
