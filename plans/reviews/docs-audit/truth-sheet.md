Threads: title, members, pinned, resolved, soft delete.

- Sessions/harnesses: claude-code, codex, opencode, cursor-agent; bring your own harness and its own key (built-in harness + model gateway removed). agent_run_config per agent: harness, model, provider, options, max concurrent sessions. Session states active/done/stopped/crashed. Work intents thread_turn, task_run, session_resume, subscription_run. watch_session reads in-memory activity buffer. stop kills the process.
- Reviews ("agent asks, human clears"): no interception; agent sends a review message, session ends; verdict → session_resume. review_sessions table maps review→session.
- Return gate exists (createReturnGate, return-enforcement, return_status tool). Harness capability descriptor exists. Part model exists (PartList, parts/*). Open handler exists (core-ui/src/services/open-handler.ts). Blocks partly (core-ui/src/block derive-blocks, messages.block_id).

- Still short of design: core→orchestration is an in-process HTTP client with actor-override header; policy not folded into invariants; websocket pushes per topic; /api/search hand-written.
