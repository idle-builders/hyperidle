## What went well

- **Producer/evaluator split paid for itself (again).** Round-1 architecture critique caught a real CRITICAL: the single code-bearing deliverable (the isolation harness) was placed in `packages/design-system`, importing `react-router-dom` + `@hyperidle/web` — violating two committed `@lore` decisions (AG4 "no react-router import in design-system"; AJ1-W3 "cross-package coupling avoided" in the DS snapshot net). That import would have broken `npm run check` from design-system (`react-router-dom` is not a DS dependency). The reviewer evidenced the violation against the live tree and pointed at the *existing* precedent in `packages/web` (`WorkBetCreate.stories.tsx` already wraps in `MemoryRouter`; `__fixtures__` already exist). Cost: one revise round. Value: avoided a typecheck-gate break + a lore violation that a green test suite would never have surfaced.
- **Honest buildable-vs-deferred line held end-to-end.** The plan split buildable (isolation harness, `designReviewDecision` gate helper, skill-edit consistency) from founder-walkthrough-deferred (live MCP annotation loop, autonomous park firing). Code review confirmed the split: AC2 / AC3-gate / AC7-skip are proven by `npm run test` + `npm run lint`; AC4 + AC5-end-to-end are inherently human-in-the-loop / external-MCP-dependent. **Nothing buildable was left as prose** — the gate mapping, the `preview/**` import boundary, and the real-surface mount are all code-validated.
- **WARNING-1 from the critique landed in the build.** The reviewer pushed for the mount test to assert against a *real* data-fed surface, not a synthetic test-local component. The builder migrated a real story (`WorkBetCreate.stories.tsx`) and `MockProviders.test.tsx` mounts the real `WorkBet` with `MOCK_BETS.b1`, asserting a real `role=heading` — discharging AC2 against a real page, not a strawman.
- **Tiny, clean code surface for an L WP.** The only shipped code: `packages/web/src/preview/` (MockProviders + index + test), `packages/shared/src/design-review-decision.ts` + test. The rest is skill markdown (`/design`, `/design-critique`, `/pipeline`, `/work-planning`, `/concept`, new `/human-design-review`). Zero snapshot re-bless (router + context providers render no DOM — matched the plan's prediction exactly).

## What cost tokens / cycles

- **One architecture revise round (6.5 → 9.0).** Single CRITICAL (package placement). Cheap relative to the break it prevented, but it is a real round: critique → revise → re-critique. The misplacement was a *plausible* default — the plan had cited the viewer's Vite relative-path glob as precedent and conflated it with a bare `@hyperidle/web/...` module specifier resolved through tsc/vitest. Producer reached for the wrong precedent; evaluator caught the conflation.
- **One mid-green guard trip (AJ1 design-source guard).** The builder's `/design` SKILL.md edit contained trigger words ("golden baseline" / "pixel-for-pixel") in a screenshot note — exactly the Playwright golden-PNG vocabulary AJ1's design-source guard exists to forbid. Guard fired correctly; cost a fix cycle (commit `be012d7d`: reworded the note + regenerated the guard attestation JSON). Guard doing its job, but the trip was self-inflicted by carrying stale-era vocabulary into new prose.
- **Stale spec required ground-truth injection.** The AJ3 spec text ("What exists today" / validation scenarios) still partly referenced the Playwright golden-PNG visual-regression world that AJ1 had already reverted to a vitest DOM-snapshot net. The orchestrator had to inject corrections so agents didn't build to the stale spec. Not a rework cycle, but a continuous tax: every agent reading the spec had to be steered off the stale framing.

## Cross-WP patterns

- **Specs drift behind shipped reality (cross-WP signal).** AJ3's own dependency (AJ1) reverted the visual-regression approach, but the AJ3 spec and downstream skill prose still carried the old golden-PNG vocabulary. This surfaced twice in one WP: (a) orchestrator injecting ground-truth corrections, (b) the design-source guard tripping on stale trigger words. Same root: **a shipped reversal (AJ1: Playwright golden-PNG → DOM-snapshot net) did not propagate into the sibling spec text or the carried-forward prose.** When a foundational WP reverses an approach, its track-mates' specs and the shared skill vocabulary become landmines. Candidate: a "spec freshness" pass when a dependency lands a reversal, or a guard/lint that flags retired-approach vocabulary in specs the way the design-source guard flags it in skill edits.
- **Critique catches contract/boundary errors invisible to a green suite (recurring — cf. AK3, AJ1).** AJ3's CRITICAL was a cross-package import boundary + lore violation. A passing test run would never have surfaced it (tests don't run `tsc` from the wrong package's resolution context, and lore is prose). This is the same class as AK3's 3 CRITICALs (false port precedent, session-less execution, CAS crash-orphan). Reinforces the producer/evaluator split (CC-009): the highest-value critique findings are boundary/contract errors, not logic bugs.
- **Lore is load-bearing and the producer doesn't always consult it.** The plan violated AG4 + AJ1-W3 — both committed `@lore`. The evaluator had to be the one to surface them. Pattern: the producer phase under-reads existing `@lore` decisions; the evaluator phase is where lore gets enforced. Candidate compound: a producer-side lore-check step (grep relevant `@lore` for the packages a plan touches) before architecture is handed to critique.

## Cost profile note — L-process WP vs L-full-stack WP

AJ3 is an L WP that was **mostly markdown + a ~120-line code surface**. It went through all 6 phases cleanly in **one orchestrator session, no builder timeout, no green-phase split**. Contrast with an L full-stack WP (multi-package schema + API + UI), which typically needs green-phase splitting and risks builder timeout. **Complexity rating L conflates "wide blast radius / many ACs / cross-cutting process change" with "large code volume."** AJ3 was the former, not the latter. Signal for planning: an L-process/tooling WP and an L-full-stack WP have very different cost profiles (session count, timeout risk, rework surface) despite the same letter. Worth a sub-tag (e.g. `L-process` vs `L-build`) so forecast/scheduling doesn't over-provision process WPs.

## Concrete signals for /compound + the A/B harness

1. **Spec-drift-behind-reversal** is a cross-WP cost source (orchestrator correction tax + guard trip). When a foundational WP reverses an approach, propagate the reversal into sibling specs + shared skill vocabulary. (New candidate.)
2. **Producer/evaluator split** caught a typecheck-breaking, lore-violating CRITICAL for the cost of one revise round — third+ instance of "critique catches boundary/contract errors a green suite can't" (cf. AK3, AJ1). Reinforces CC-009.
3. **Producer-side lore consultation gap** — the plan violated two committed `@lore` decisions; only the evaluator caught them. Candidate: lore-grep step in `/architecture` for touched packages before critique.
4. **Complexity L is overloaded** — process/tooling-L and full-stack-L have divergent cost profiles. Candidate sub-tagging for planning forecast accuracy.
5. **Self-inflicted guard trips from carried-forward vocabulary** — the design-source guard tripped on golden-PNG words copied into new prose. Guard worked; the lesson is that retired-approach vocabulary lingers in agent-authored text and should be scrubbed at the source (the spec).
