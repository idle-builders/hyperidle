## 1. Context

`packages/server/src/app-runtime/` is the last transitional owner: 65 files / ~16k lines, a barrel (`index.ts`, 481 lines re-exporting everything), a grab-bag boot shell (`bootstrapAppRuntime`), and a package export (`@hyperidle/server/app-runtime`). It is isolated from harness *types* by injection (`dispatcherDeps` is opaque) but is still a distinct third runtime owner between Core app and Agent layer. The should graph has two owners. AU11 dissolves the third by relocating each responsibility to its final home and deleting the shell artifacts.

Nothing here is a behavior change. The proof of preservation is that the ~110 importers (mostly tests) are repointed **import-path-only** and stay green. §5 is the load-bearing invariant: at every call site only the import path moves — timing, arguments, and semantics stay observably identical, no test assertion changes.

**`routine-scheduler.ts` decision (from refine open question) — DECIDED: option (b).** The scheduler classifies **Core — Routine** (cron/due-evaluation + `recordAgentWorkIntent` + `checkAndFireRoutine`) and lands in `packages/server/src/services/`. Its **agent-selection call stays where it is, unchanged: fire-time, same timing, same semantics.** Verified in source: `agent-work-intent-worker.ts`'s `routine_run` branch does NOT select an agent today — it uses `routine.ownerAgentId` directly (~lines 198-227); the WIP-limit + delegate selection runs at fire-time in `routine-scheduler.ts:379-386`. Pushing selection into the intent resolver (the previously-preferred option a) would relocate fire-time selection into drain-time — a real behavior change (WIP state can differ between fire and drain → a different agent chosen) that violates §5's import-path-only invariant. AU11 therefore takes option (b): the scheduler's `import { isAgentAtWipLimit, selectAgentByAppDefaults } from "./agent-selection.js"` is **repointed to `agent-selection`'s new agent-owned `services/` home** (a pure import-path move; the call is byte-identical). The residual core→agent-selection dependency direction is recorded as a `@lore` note + AU8 boundary item — a deeper worker-side rearchitecture (moving "which agent" fully to drain-time) is **out of scope for AU11** (future AU8-class work). AC-2's forbidden set is harness adapters / MCP bridge registries / provisioning internals / context assembly / tool execution / agent lifecycle internals — `agent-selection` (a "which agent" contract, no harness/adapter/provisioning reach) is **not** in that set, so this residual edge is guard-clean; it is a should-graph purity item, not an AC-2 violation.

## 4. Acceptance criteria → verification

Mirror of `requirements.md §4`. Each AC has: (1) the `au11-runtime-ownership-guard.ts` static check, and/or (2) `npm run check`, and/or (3) the existing behavior test suite repointed and green, and/or (4) the Phase-4 should-graph audit.

**Guard's core-vs-agent allowlist (NOTE 3 — pinned explicitly).** Core and Agent services **share** one directory, `packages/server/src/services/` (AU9 precedent: flat + allowlist, no `services/agent/` subdir). The guard therefore separates the two owners by an **explicit agent-owned allowlist constant**, not by directory. That allowlist =
**AU9's already-landed agent-owned service set** ∪ **this WP's §2 13 agent-destined files** (`context-assembly`, `context-assembly-prompt`, `session-context`, `writeback`, `file-watcher`, `polling-watcher`, `roster`, `contracts`, `agent-selection`, `task-dispatcher`, `assistant-dispatcher`, `cost-cap`, `cost-sentinel`, `routine-session-reaper`, `sandbox-reaper`, `provision-registry`, + the `builtin-routines` handler-split landing file). The guard pins this as a named constant so it does not ambiguously flag a legitimate agent-owned `services/*` file as a core violation (or a core `services/*` file as agent). Any future move updates the constant in one place.

**AC-2 descriptor-read vs adapter-execution AND type-only imports (NOTE 4).** AC-2's guard must encode two allowances so it does not false-positive: (a) Settings surfaces (`harnesses.ts`, `mcp-route.ts`, `connections.ts`) reading harness/MCP *descriptors/capabilities* are allowed while *adapter* imports fail; (b) **`import type { ... }` of the now-agent-owned `contracts.ts` is an allowed edge** — a type-only import is a compile-time contract dependency, not an execution dependency, so a config resolver (`agent-defaults/resolvers.ts`) or core consuming agent-contract *types* must not trip the guard. The guard distinguishes `import type`/type-only specifiers from value imports. Guard verified by `--fixtures` catching a direct and a transitive value leak (au10 pattern).

## 7. Trade-offs & open questions

- **Directory churn vs. minimum cut.** New `knowledge/`+`notifications/` homes are high churn but are the minimum that satisfies AC-4 ("no grouping under a name"); leaving files in `app-runtime/` with only the barrel gone still groups them. Accepted.
- **New `@hyperidle/server/routines` public export.** Adds one curated cross-package seam so `packages/eval` (the only cross-package consumer, 4 scenario files) keeps importing the three routine functions after `./app-runtime` is deleted. Cost: one thin re-export file + one package.json export entry. Rejected alternatives: (a) deep `src/` import from eval — disallowed cross-package; (b) two granular exports pointing at internal files — couples eval to internal layout across the builtin-routines split, and re-exposes files whose home shifts mid-WP. A single stable `/routines` public API is the lower-coupling choice and is idiomatic (cf. `./tools`, `./schemas`). `packages/db` needs **no** export — its references are comments.
- **`routine-scheduler` residual core→agent-selection edge.** Option (b) keeps fire-time selection unchanged (behavior-preserving) at the cost of a core-Routine→agent-selection import. Not an AC-2 violation (agent-selection is a "which agent" contract, not harness/adapter/provisioning/context/tool/lifecycle). Filed as an AU8 boundary note; drain-time-selection rearchitecture is deliberately out of AU11 scope (it would be a behavior change).
- **AU8 dependency:** AU8 (full graph guard) is blocked on AU11. AU11's guard is deliberately scoped to the boundary it cuts — do not attempt the full graph here (that was an explicit AU10 review check against scope creep).
