# AU20 — Service surface census (as-is, post-build)

Generated by `scripts/surface-census.ts` (re-runnable: `npx tsx scripts/surface-census.ts --table`).
Counts **exported declarations at the implementation site** — where the `export function` /
`export const` / `export class` / `export type` / `export interface` keyword actually is — NOT
resolved through barrel re-exports. Methods = function | const-value | class | enum. Types =
type | interface.

Diffs the **before** (pre-AU20, commit `42c38e9a`, 31 services) against the **after** (post-AU20,
23 services). The **should** column is the per-service target from the AU20 concept plan (barrel
target; shown for reference — it was a *public-API* target, not an implementation-declaration one).

## Two measures — read them together

| Measure | Before | After | Δ |
|---|---|---|---|
| **Public barrel API** (`generate-dependency-graph.ts` — what a service exposes to *other* packages) | 1218 | 630 | **−48%** |
| **Implementation exports** (`surface-census.ts` — every `export` declaration in the service's code) | 1277 | 1237 | **−3%** |
| — methods | 670 | 646 | −24 |
| — types | 607 | 591 | −16 |

**The gap between these two rows is the headline finding.** The *public surface* nearly halved, but
the *implementation* barely moved. AU20 overwhelmingly **internalized** exports (dropped a barrel
re-export line) rather than **deleting or truly merging** the code. `check`/`lint`/`test` pass
regardless of how many `export function`s sit inside a package, so nothing mechanically forced the
method *bodies* to be removed — only un-exposed.

## Findings

1. **The 3 merges concatenated; they did not collapse.** `run-orchestration` (session-runtime) is
   the *exact* sum of its four parts — 56 methods / 118 types = 15+18+16+7 / 22+53+28+15. The merge
   moved code into one package and deleted the package boundaries + cycles (real wins), but never
   unified the combined API into one coherent small surface. `session-requests` and
   `harness-registry` likewise grew rather than shrank. **This is the single biggest "kept more than
   planned" driver** — the plan's per-service targets assumed each merged product would be ONE small
   API (~15–20); the anchors landed at 174 / 108 / 87.

2. **The biggest domains grew at the implementation level.** `knowledge` (+10), `notifications`
   (+16), `work` (+23) added their new general interfaces (`list(filter)`, `get`, `transition`)
   *on top of* internalizing the old per-caller methods — net *more* declarations, not fewer. The
   public barrel shrank; the code grew.

3. **Genuine reductions did happen — in the leaf domains.** `conversation` (−15 methods), `users`
   (−11), `connections` (−10), `org` (−8), `review` (−32 total, mostly collapsing 32 types → 7),
   `routine` (−6): these are where per-caller sprawl was actually deleted/merged, not just hidden.

4. **Methods vs types both ≈flat at implementation.** Methods 670→646, types 607→591. Types were not
   the story either way; the story is barrel-internalization vs. real deletion.

## Implication

The public-API goal ("what does a service *deliberately expose*") was substantially met (−48% barrel
surface, cleaner coupling: 139→89 DI edges, 3 cycles removed). The deeper goal ("reduce the method
sprawl") was only partly met: ~6 leaf domains genuinely shrank, but the merged anchors and the big
domains did not — the sprawl was largely internalized, not removed. A follow-up pass that (a)
collapses the 3 merged anchors' concatenated APIs into one coherent surface each, and (b) deletes the
now-internal-but-still-present duplicate method bodies, would convert the −3% implementation number
toward the −48% the barrel already shows.
