### CRITICAL
- **[plan §"Per-file — Hover vs Selected (§4)" + §"AC → validation"]** The slash-menu fix is className-only but the divergence is **behavioral**, and the plan ships an unsatisfiable verification. Verified `slash-menu.tsx:218`: `onMouseEnter={() => setSelectedIndex(index)}` — pointer-hover *sets* `selectedIndex`, so hover and selected are one state. After the planned swap (`index===selectedIndex` → accent; else → `hover:` neutral), a hovered item satisfies `index===selectedIndex` and renders the **accent** tint; the `hover:` neutral branch is dead for pointer users. The plan's own e2e ("hover item A + select item B, assert A neutral, B accent") therefore **cannot pass** — hovering A makes A selected. → The plan must either (a) explicitly decouple `onMouseEnter` from `setSelectedIndex` and document it as a sanctioned behavior change (it conflicts with the stated "No component API changes — only chrome converges" constraint, so it needs a written waiver), or (b) re-target the hover-vs-selected validation onto a component that holds both states independently (the plan already names TabBar as correct). As written, task 6 builds a fix that the task-6 proof contradicts. This blocks `/write-tests` — the red test would be impossible to make green honestly.
