## Key observations

### Successes

**S1: Gitignored live-proof artifact pattern worked.** The `.annotations/` directory correctly stayed gitignored (holds transient session state). AC11's "live-proof" AC was satisfied by committing a *tracked* `plans/AJ5/live-proof.md` capturing the real rendered two-round `annotations.md` output (both `## Round 1/2` headers, fiber-resolved component names, real note text). This de-hoaxes the AJ3 external-MCP fantasy: genuine end-to-end proof was generated by driving the real `handleAnnotationRequest` → `appendAnnotation` → `renderMarkdown` code path (POST→/round→POST → 200/200(round:2)/200, markdown reproduces both rounds, path-traversal guard tested). Pattern is now established for future "live-proof with gitignored state" workpackages.

**S2: Approved-design checklist at green phase prevented rework.** The design critique Phase 2 flagged three outline-state ACs (hover/selected/saved) as explicitly RESOLVED in the approved design. During code review (Phase 4), the gap showed up (W1 warning: states unimplemented). Builder caught the delta and committed a fix (bf45fe84, +289 test lines, 3 class-based outline transitions). The structured two-lens code review (design context carried forward from Phase 2) caught what a single-pass review would have missed. Pattern matches W2, T5, U6 — carried design/arch context in code review is load-bearing.

**S3: TDD red-phase discipline paid for itself.** 50+ failing tests written before any implementation (Phase 3). Tests passed on first green-phase run, with all design-state tests also passing immediately after the W1 fix. No "test flakiness," no test-writing debt. Red phase forced AC clarity upfront (AC1–AC11 explicitly enumerated in test blocks before code). Pattern matches N4, R5, R6, U4, U11, W2, X2 — high confidence that pre-spec tests prevent rework.

**S4: Lore captures worked load-bearing.** 12+ `@lore` comments scattered through annotation modules (fiber brittleness, dev-only-no-bundle, one-shot arm semantics, fixed-to-pill popover, MD-derived-clobber warning). ### Friction + cost signals

**F1: AC11 live-proof had to be re-created as a tracked artifact.** The code-review verdict (2b51dbfc) flagged C1: AC11 unproven because `.annotations/` is gitignored and the PR body had no rendered two-round markdown. Builder correctly understood the requirement (gitignored state cannot enter the diff) but initially didn't create a tracked evidence file. Required two separate fix commits: first `dc482bc0` ("C1 — tracked live-proof") created `plans/AJ5/live-proof.md` with the real rendered `.md`. Pattern: when a live-proof lane requires gitignored state, the artifact *must* be captured in a tracked file (non-gitignored, persisted across worktrees). This was understood by the builder but cost an extra round-trip. **Process note:** /write-tests should enumerate live-proof ACs explicitly ("requires tracked artifact capture") so red-phase tests verify both mechanism + evidence.

**F2: Approved-design states had to be implemented in a second fix commit.** W1 warning (2b51dbfc code review) flagged three outline classes specified in `approved.md` but unimplemented in code (hover nearly invisible, `.anno-selected` absent, `.anno-saved` absent). Builder responded with bf45fe84 (+289 test lines, 4 new test blocks asserting the class transitions). This was not a mistake — green-phase implementation can legitimately defer design details — but it cost a code-review round + one fix commit. **Process note:** checklist verification would help: "For each design-state row in approved.md, confirm corresponding CSS class + test assertion exists." This is preventable by a simple scan during Phase 4 green but currently requires reviewer vigilance.

**F3: Environment friction: full `npm run verify` blocked by pre-existing dependency absence.** The test attestation (43ec92e7) succeeded for the design-system subset (`npx vitest run viewer/annotations` → 53/53; catalog-snapshot → 255/255 green) but full `npm run verify` cannot run because `@anthropic-ai/claude-agent-sdk` is not installed locally (server/pipeline typecheck fails). This is a pre-existing, unrelated issue (main is clean) but it blocks the local `/ship` verify/attestation gate. **Implication:** AJ5's full attestation was honest (design-system 1034/1034 pass, zero failures in AJ5 code) but the verify report is incomplete. The `/ship` skill depends on `npm run verify` passing or an honest attestation explaining why — this environment cannot run full verify locally. **Note for ship:** flag this pre-existing environment issue in the ship attestation so CI does not inherit the broken baseline.

### Patterns worth feeding to /compound

**P1: Approved-design checklist at green phase (CC-001 prevention).** Multiple workpackages (T5, U6, W2) have had design critique findings unresolved at green phase. AJ5 benefited from a structured design-context carry-forward in code review (reviewer had access to `approved.md` side-by-side with implementation). Pattern: add a mandatory checklist to `/write-code` red phase → "For each design state/interaction in approved.md, write a failing test that asserts the CSS class / DOM structure / event behavior exists." This pushes design-state specification into the red phase where it surfaces early.

**P2: Gitignored state + tracked artifact evidence (F1 pattern).** When a workpackage's live-proof depends on gitignored transient state (session data, temp files, dev-only output), the pattern is: run the real code path, capture the output in a *non-gitignored* tracked artifact (e.g., `plans/<id>/live-proof.md`), commit it as evidence. The gitignored dir stays clean (transient state resets per session); the tracked file is the durable evidence. This pattern is now explicit in AJ5 and should be documented in `/concept` or `/architecture` guidance for future dev-tool workpackages.

**P3: TDD red-phase correlation confirmed (CC-010).** Workpackages with >40 pre-spec tests written before code (N4, R5, R6, U4, U11, W2, AJ5) have zero MUST-FIX blockers in code review and pass in 1 round. Workpackages that skip or defer red phase (U11 partial, T2 E2E skipped) require rework cycles. Pattern is statistically strong — recommend /compound create a "TDD red-phase discipline" SOP that /write-tests enforces.
