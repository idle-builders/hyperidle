## Server Auth Fallback

**Files:** `packages/server/src/middleware/auth.ts`, `packages/server/src/routes/auth.ts`, `packages/server/src/__tests__/lifecycle-propagation.ts`

**Symbol:** `u-founder` (literal-id, 5 rows in inventory.json)

**Why it exists:** The auth middleware falls back to the hardcoded user ID `"u-founder"` when the database contains no human user record. This is a safety net for unseeded databases and existing integration tests that do not seed a user. The `routes/auth.ts` similarly falls back to `"u-founder"` when the session context does not carry a resolved user ID.

**Remediation plan (DB migration path):** The server auth fallback will be removed as part of the onboarding and database seeding story. When a new installation runs the migration, a seed script will insert the founder user record with a real UUID. After that migration, the fallback is unreachable and will be deleted. The `u-founder` string will be replaced by a nullable `userId` that surfaces a 401 when absent rather than silently substituting a fake ID.

**Dependency:** Blocked on the user-profile and onboarding workpackage (see plans/work-packages/).

## Knowledge Page API Wiring

**Files:** `packages/web/src/fixtures/knowledge-data.ts`, `packages/web/src/pages/KnowledgeDetail.tsx`

**Symbols:** `MOCK_KNOWLEDGE_ITEMS`, `MOCK_CURATION_SUGGESTIONS`, `LEGACY_DETAILS`, `LEGACY_SOURCES`, `FALLBACK_DETAIL`, `../fixtures/knowledge-data` (import)

**Why it exists:** The Knowledge List and Knowledge Detail pages (`KnowledgeDetail.tsx`) were built with fixture data (`MOCK_KNOWLEDGE_ITEMS`, `MOCK_CURATION_SUGGESTIONS`) before the knowledge API endpoints existed. The `LEGACY_DETAILS` and `LEGACY_SOURCES` constants in `KnowledgeDetail.tsx` are kept temporarily because the protected E2E fixture `k1` uses `layer:"L0"` and `kind:"decision"` fields that only exist in `LEGACY_DETAILS`. The `FALLBACK_DETAIL` constant provides a null-object default when the API has not yet returned data.

**Remediation plan:** Wire the knowledge page to the real API endpoints:
1. Replace `MOCK_KNOWLEDGE_ITEMS` with a `GET /api/knowledge` query via the existing React Query hooks.
2. Replace `MOCK_CURATION_SUGGESTIONS` with a `GET /api/knowledge/curation` endpoint (to be built).
3. Remove `LEGACY_DETAILS`, `LEGACY_SOURCES`, and `FALLBACK_DETAIL` once the API returns all required fields including `layer` and `kind`.
4. Update the E2E fixture `k1` to use API-seeded data rather than client-side constants.

**Dependency:** Blocked on the knowledge API completion story (L23 wiring).
