### CRITICAL
- [§1a / §6 / §8, AC-4] **`packages/eval` is entirely unaccounted for and contains a real generic `factorySettings` writer.** `packages/eval/src/seeding.ts:267` exports `seedFactorySettings(db, Record<string,string>)` which does `.insert(factorySettings).onConflictDoUpdate(...)` — a generic KV writer — called from 8+ sites (`scenarios/builtin-routines.ts`, `scenarios/session.ts`, `scenarios/routine-sessions.ts`, `seeding.ts:339`). `packages/eval` IS in the root `tsconfig` project references (`{ "path": "packages/eval" }`), so dropping the `factorySettings` export from `schema.ts` + the `packages/db/src/index.ts` barrel breaks eval's compile. Worse: the plan's AC-4 verification (`git grep factorySettings packages/server/src packages/db/src → empty`) is scoped to server+db only, so it returns **green while eval still references the dropped table and `check` is red** — a false-green AC-4. The plan's §1a "14 in server +2 in db = 16" headline undercounts by omitting the eval accessor + its call sites. Fix: bring `packages/eval` into the change scope, the migration ordering, and the §9 fixture-rewrite list, and widen the AC-4 grep to the whole repo.

- [§4, AC-5] **The `cost_actual` live-compute swap silently breaks the graded cost-sentinel eval scenarios.** `scenarios/builtin-routines.ts` and `scenarios/routine-sessions.ts` seed `cost_actual` **directly** (`8500`→warning, `10500`→breach, `5000`→ok, `1001`→blocked) plus `cost_cap` to drive `cost-sentinel.ts`/`routine-scheduler.ts` behavior **without accumulating any user cost**. §4's premise "live `sumAllUserCost` equals the previously-stored `cost_actual`" is false on this path — `sumAllUserCost` is ~0 in these evals, so warning/breach/blocked all collapse to ok/allowed. AC-5 (behavior unchanged) is violated for the eval suite, and the plan never lists these files. This is exactly the plan-vs-reality conflict that becomes a mid-build BLOCKER + burned round. Lock the resolution NOW as an architectural decision (rewrite the eval scenarios to accumulate real user costs and seed `server_config.cost.capMinor`), do not leave it as an unlisted surprise. (Prod behavior IS preserved — confirmed `cost-cap.ts` writes `cost_actual = sumAllUserCost` after every event today; the break is eval-only, but eval is graded infra and gates compile.)

- [§6 / §8, AC-6b] **AC-6b ("reintroduce a factorySettings-shaped raw table … fails a lint-time guard, not merely convention") is unmet as written.** The plan argues deleting the `factorySettings` symbol makes any reference a `check` failure, so no guard is needed, and punts a shape-guard to AU8. But AC-6b targets a *new* `pgTable("...", { key, value })` cross-domain table — table-deletion gives **zero** enforcement against that; a new generic KV table compiles clean and passes `check`. Compile-error-on-the-old-symbol is stronger than convention for the *old* table but is not the "lint-time guard" AC-6b names for the *shape*. This is the single highest-risk interpretive call in the plan and it lands on the wrong side of the founder's zero-exceptions/"not merely convention" rigor. Resolve by either (a) an explicit written spec-owner ruling that AU8's generic guard owns AC-6b and it is formally descoped from AU18, or (b) a minimal shape-guard shipped in AU18. Do not ship on the current convention-substitution reading.

- [§3, `routes/agents.ts` GET /templates/:role] **Path-traversal sink introduced by the docs-file template read.** The plan moves template reads from a DB key lookup (`factorySettings.system_template:<role>`, traversal-safe) to a filesystem read of `docs/system-prompts/${role}.md`, with `:role` flowing straight from the route param and no sanitization named. `../`-style roles escape the docs dir. The current design has no traversal risk; the plan adds one without naming the mitigation. Specify allowlisting `role` against the known factory roles (`packages/shared/src/factory-roster.ts`) or rejecting non-`[a-z-]` before the read. (Per ETHOS this is an earned boundary — untrusted route input reaching a filesystem sink — not preemptive paranoia.)
