# Migrations — hand-written, on purpose

Migrations in this folder are written by hand (usually by an AI agent), not
generated by `drizzle-kit generate`. There is no generator step in this repo.

## Why

`drizzle-kit generate` diffs the current `schema.ts` against a stored
"snapshot" of the schema as of the last migration, and emits DDL for the
difference. That works for additive column/table changes, but this repo's
migrations regularly need things a diff-based generator cannot express:

- **Ordered backfills** — populate a new column from existing rows before a
  `NOT NULL` constraint goes on it.
- **Row-by-row conversions** — reshape JSON blobs, split one column into
  several, or fold several rows into one.
- **`RAISE EXCEPTION` guards** — refuse to apply a migration when the data in
  front of it doesn't match what the migration assumes, instead of silently
  corrupting it.

None of that is a schema diff. Hand-authoring is not a workaround here — it's
the only way to write migrations this repo actually needs, so a generator
was never load-bearing to begin with.

## Adding a migration

A new migration is:

1. A hand-authored `NNNN_description.sql` file in this folder, `NNNN` one
   higher than the last entry.
2. A matching entry appended to `meta/_journal.json` (`idx`, `version: "7"`,
   a `when` timestamp in epoch ms, and `tag` matching the file name minus
   `.sql`).

No schema snapshot is written or read for this — `meta/` only ever held
snapshots as the "before" side of `drizzle-kit generate`'s diff, and nothing
else reads them. `drizzle-kit migrate` (`npm run db:migrate`) and the
runtime `applyMigrations`/`migrate-pg.ts` paths apply migrations by reading
this folder's `.sql` files against `meta/_journal.json` directly — neither
needs a snapshot.
