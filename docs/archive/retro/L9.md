All 6 acceptance criteria verified: (1) one queue + one detail, legacy redirects no 404; (2) detail renders picked thread with L1 rich messages inline; (3) naming collision resolved (one `Conversations` page); (4) Vitest covers dispatch + unknown-thread fallback; (5) Playwright e2e Work → click bet thread → detail renders (AC satisfied via `L15-task-request.spec.ts:303–314`, though L9-specific test has dead-code path); (6) `bun run check` + `bun run lint` + `bun run test` green, local e2e green (CI in-flight, authorized for merge on local-green per founder).

## What worked

1. **Concept-first locking held under critique pressure.** Designer's insight ("ThreadShell already dispatches by message type via L1 discriminant exhaustiveness — page does not need per-shape branching") removed a whole class of routing-logic risk. Both Architecture and Code Review confirmed the shape. No rework during build.

2. **Tripwire-style edge-case testing.** Builder included a unit test for whitespace-only thread id (`?id=%20%20%20`), directly addressing the Phase 2 CRITICAL finding. No test rewrite needed; the case was covered before Phase 3 shipped.

3. **Same-reviewer warm-from-Phase-2 pattern.** Phase 4 code reviewer carried Phase 2 critique context forward: all 7 carry-over items (CRITICAL trim guard, WARNING Outlet-context, 5 suggestions) appeared in a verification table with PASS / FAIL / evidence. No design re-discovery during code review. The 6/6 ACs audited cleanly on first pass.

4. **Clean architecture layer boundary.** All changes inside `packages/web` (Human Interface). No Meta layer reach. No backend modifications. Reviewer verified layer integrity at 10/10.

5. **Single-variant design efficiency.** The design space was naturally tight (replace two routes with one, no new UI primitives, no per-shape branching). Designer shipped concept + design + architecture in one dispatch. Eliminated 2–3 variant exploration cycles.

## What hurt

1. **CI workflow coalescing on draft PRs.** After builder pushed test → feat → lint-fix in rapid succession, only the FIRST push triggered CI. The next two pushes never produced runs. Likely cause: `.github/workflows/ci.yml` has `concurrency.cancel-in-progress: true`, which coalesces rapid pushes on draft PRs. Even an empty re-trigger commit didn't fire CI. **Cost:** Pipeline rule built in "CI is the verify gate" with max 3 retries; at ~28 min per CI cycle, even one retry loop blocks for nearly an hour. Founder intervened and authorized advancing on green local verify. **Signal:** Local-green (check + lint + test + Playwright) should be the Phase 4 gate; CI is async post-merge confirmation, not a pipeline blocker. This friction is the strongest compound candidate — it will hit every multi-push story.

2. **Stale lint baseline.** Builder pushed code that passed `bun run verify` locally but failed CI on a `assist/source/organizeImports` violation in `Conversations.stories.tsx` (newly added). Possible root: local biome config differs from CI, or the stories file wasn't in the local lint scope. One-line fix (`organize imports`). **Cost:** 1 extra commit, 1 CI cycle (blocked by #1's coalescing). **Signal:** Either the local verify baseline is drifting from CI, or the file list for lint is incomplete.

3. **Stale e2e references missed in planning.** Architecture plan enumerated ~14 e2e specs that need testid migration (`conversations-review-page` → `conversations-page`). One spec was missed: `navigation.spec.ts` also referenced the old testid. Plan review should have caught this with a pre-emptive grep; instead it surfaced during full-suite local run in Phase 3. **Cost:** 1 extra commit (a4204ec). **Signal:** Architecture Suggestion #4 flagged this as a risk class ("renames surface in e2e"); the pre-emptive grep would have been <2 min effort. E2E ripples are now a flagged risk — explicitly enumerate them in future architecture critique.

4. **Stale branch resume with `attempts: 3`.** Pipeline state showed the branch had `attempts: 3` from a prior abandoned run (2026-04-30); local progress.json had `currentStep: 10` (stale). Branch had no unique commits but local state was stale. Resolved by deleting and recreating. **Cost:** Manual intervention, confusion in the run log. **Signal:** Pipeline resume logic should detect `git log <branch> ^main` empty (no unique commits) and reset cleanly, OR cap-and-block instead of silently re-using stale state.

5. **Misleading e2e test path (non-blocking finding).** `L9-single-detail.spec.ts:236–339` AC-5 test looks for a non-existent "open in conversations" button, finds nothing, then silently falls through to direct `page.goto()` of the URL it constructed. That is a tautology (proves "we can goto a URL", not "Work → click → detail"). The actual AC-5 click-through is covered by `L15-task-request.spec.ts:303–314`, so the AC is verified — but the L9-specific test is misleading. Phase 4 flagged this as MED (non-blocking, carry-over to follow-ups). **Cost:** Test gives false confidence; no runtime cost.

## Compound candidates

Scanning `.pipeline/retro-log.jsonl` (to be created) and cross-referencing prior work packages (L15, L16, L18, L23):

1. **CC-???: CI duration vs pipeline gates (STRONGEST COMPOUND).**
   - **Occurrences:** L9 (#1 above); L15 (multi-round e2e selector rewrites); L16 (synthesis e2e regression). Same root: external gates (CI, e2e ripple sites) with long lead times block the pipeline.
   - **Severity:** MED (pipeline blockage, ~1 hour per occurrence).
   - **Evidence:** L9 log above; L15 retro (3 e2e rounds); L16 retro (synthesis mock ripple); L18 (multi-cycle e2e churn).
   - **Recommendation:** Adopt "local-green is the Phase 4 gate; CI is async confirmation" as the policy. Update `/pipeline` skill to surface CI as a *parallel task*, not a blocking gate. Builder ships when local verify passes; CI confirms post-merge and reports failures async. This will require a toggle / founder sign-off on edge cases (auth changes, schema migrations), but for UI-only stories, it removes ~1-2 hour blockers from 30% of workpackages.

2. **CC-???: E2E ripple-site enumeration (SECONDARY).**
   - **Occurrences:** L16 (synthesis e2e missing mock); L9 (navigation.spec.ts testid missed in plan); L18 (multiple e2e specs touched post-ship).
   - **Severity:** LOW (1–2 extra commits, caught by testing).
   - **Evidence:** L16 retro §Patterns #1; L9 code-review §Findings "Stale e2e references"; this retro #3.
   - **Recommendation:** When a story changes runtime data paths, removes fallbacks, or renames UI elements, the architecture should explicitly list "E2E ripple sites: `<spec1>`, `<spec2>`" with a count of expected migrations per spec. Critique should grep to confirm. A 2-min pre-check prevents 1 extra commit.

3. **CC-???: Pipeline resume with stale state (TERTIARY).**
   - **Occurrences:** L9 (branch had `attempts: 3`, no unique commits, stale `currentStep`); prior abandoned runs.
   - **Severity:** LOW (manual fix, confusion).
   - **Evidence:** L9 task brief "Stale branch resume" + this retro #4.
   - **Recommendation:** When a branch resumes, check `git log <branch> ^main` length. If empty (no unique commits), either reset to current main or block-and-ask. Don't silently re-use a stale `currentStep` counter. Add 1 line to the pipeline harness: `if (git log output is empty) reset or block.`
