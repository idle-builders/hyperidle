Director's cut · Rev 01 · Design system & shell

The system underneath.

Version A is a tweakable design-system sheet — HyperIdle.html — with opinionated accent tokens, density modes, rail states, and a single-theme aesthetic ("Silent Intelligence"). Version B is the real shipping shell in packages/web/src — Tailwind + daisyUI theme factory-dark, React primitives, AppShell.tsx, a live viewport-driven responsive system. This document takes the token scale and aesthetic discipline from A, reconciles them with the component contracts and responsive rules in B, and documents every deviation so the front-end team can land the changes against real files.

What we kept, what we changed

From Version B (canonical): the six-step surface ramp (--surface-0 … --surface-6), the three-tone text scale (--text-hi / -mid / -lo), the daisyUI semantic names (primary / secondary / accent / warning / error), the viewport breakpoints (1024 / 1280), the four-view ViewId union, the sanitizeRouteId contract, the useRovingFocus keyboard model. From Version A (visual & density): the 2px left-edge active indicator on IconRail items, the submenu section groupings (unread count in header, blocking pinned to top), the ghost-filled search field, the mono eyebrow typography, the "float shadow" on floating surfaces, the deliberate no-border discipline (tonal layering only). New (agreed on today): a canonical Settings drawer shape (not a modal — a right-side sheet sharing space with the Rail), a proper Command-K overlay with the same keyboard-nav contract as the rail, and the 56px collapsed Rail that still shows the three key pills (Blockers / Reviews / Paused) — A had nothing when collapsed, B shows only counts without semantic color.

01 · Tokens
Surface & text scale
Seven surfaces --s0…--s6 + --ghost. Text scale --t-high / -mid / -low. Custom accent swap via Tweaks (ice / sage / ember).
Same seven surfaces (--surface-0…-6) in index.css, plus daisyUI semantic names in tailwind.config.ts (primary #adc6ff, secondary #d58f24, accent #bbffb3, error #ee7d77). Single theme.
B wins on naming — daisyUI semantics win because every component already reads them. A wins on density knob — port the Tweaks → density setting into SettingsData.appearance.density (it already exists; it just doesn't do anything). Drop A's accent-swap: single theme, single accent. Winner · hybrid
02 · IconRail
Active state affordance
40×40 button, surface-4 fill when active, 2px left-edge rail in --primary. Also shows a 6px notification dot for inactive views with unread.
daisyUI btn btn-ghost btn-sm with btn-active class. No edge indicator, no notification dot. Fully keyboard-navigable via useRovingFocus (good).
A wins on affordance. Adopt the 2px edge-rail and the unread dot — these map directly to real product signal (you need to see "there's something in Conversations" without switching). Keep B's roving focus and ARIA. Winner · A
03 · Rail collapsed
What survives the collapse
Rail states designed but collapsed state just shows three count pills with semantic color (danger / warn / neutral) — you learn at a glance that something is blocking.
Rail.tsx when collapsed: w-14 column with two neutral badges (bet count + blocker count) and an expand chevron. No color semantics, no "paused" surface.
A wins. A collapsed Rail should still communicate. Three semantic pills — BLK (error), REV (primary), PSD (neutral) — plus a click-to-expand chevron. The color is the whole point. Winner · A
04 · Submenu
Header & filters
Title + total count in mono, segmented filter row (All / Needs review / Chats / Resolved), ghost-fill search with ⌘K hint.
Plain <span> title + collapse button, NavItem list. No filters, no search in the submenu itself — search is delegated to the ⌘K global.
Hybrid. Keep B's separation of concerns: global search stays ⌘K-only, not a submenu field — doing both is noise. Adopt A's mono header + count bubble, and port A's segmented filter row but only for views where filtering is a real task (Conversations yes, Knowledge yes, Work no — the board already is the filter). Winner · hybrid
05 · Responsive
When does the shell fold?
Single desktop mock. The rail-toggle buttons in the prototype are a design affordance, not a responsive rule.
useViewportBreakpoint: Submenu collapses <1024px, Rail expands ≥1280px. Per-axis manual override once the user toggles.
B wins, unambiguously. The breakpoints are correct and the override model (null = follow viewport; true/false = user choice persists) is the right UX. A's prototype should cite these breakpoints in its tweak panel instead of hiding them. Winner · B
06 · Settings
Modal, drawer, or page?
Settings is a fifth view (icon at bottom of rail) with a full-page submenu for sections (Profile / Agents / Notifications / Appearance / Products).
SettingsPanel opens as a modal triggered by avatar click or ?settings=open. Full settings tree inside, but overlays the shell.
Neither — synthesize. Settings is configuration, not a destination. But modal is too disruptive. Target: right-side drawer (w-[420px]) that slides in, pushing the Rail out and leaving the Submenu + Main visible. Section list stays inside the drawer. Closes on Esc or outside-click — the useCommandK pattern already models this. Winner · new
07 · Command-K
Where does search live?
Submenu search with ⌘K hint inside the ghost field. No dedicated overlay shown — the hint is a promise not a feature.
GlobalSearchPanel is real (useCommandK, sanitizeRouteId, handleSearchNavigate). Opens on ⌘K, routes by type (conversation / work / knowledge). No visual design committed — it's a primitive daisyUI modal.
B wins on substance, A on surface. Keep B's routing + id sanitization. Give it A's visual treatment: centered 640px overlay, ghost search field at top, grouped results (Conversations / Work / Knowledge), keyboard-nav with arrow keys + Enter, mono recent-queries row at bottom. Winner · hybrid
