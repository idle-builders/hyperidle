# L15 retro

**Workpackage:** L15 — Strip Kanban drag; add request-state-change + start-thread
**PR:** #63
**Date:** 2026-05-04
**Run mode:** non-AB (real ship intent)

## Run shape
- Phases: 5/5 complete.
- Critique rounds: design 1, architecture 2.
- Review rounds: 2 (NOT DONE → DONE).
- CI fix iterations: 3 push series after initial GREEN.

## Observations

### Worked well

1. **One-dispatch designer output** — Phase 1 designer shipped concept + 3 design variants (scored + picked C) + architecture in a single turn. This compressed what could have been 3 sequential phases into 1. The three variants (kebab, header strip, sheet) were scored against a 9-dimension rubric; the decision frame (growth into L18 attached-thread surface without rework) was explicit and justified. No rework required in Phase 2. Pattern: when the designer has clear probes and evaluation criteria, one-turn output is possible.

2. **Explicit protected-test contract enforcement** — Architecture-critique R1 flagged that `WorkTeam.test.tsx:73-90` (a frozen I4 contract on `COLUMN_TO_STATE` shape) would break after drag removal. The fix was enumerated in §F.1 ("Protected tests retired"), integrated into the ordered task breakdown (step 3), and executed cleanly. This is CC-008 pattern maturity: the pipeline now catches and documents silent protected-test removal. No surprise failures post-ship.

3. **Incremental focus management fix** — Phase 4 Review R1 called out F1 HIGH (no focus trap, no focus restoration) as a design contract break. The fix in R2 snapshot-on-open + wrap-on-Tab + restore-on-close is the standard React pattern, was tested with 4 regression cases, and introduced zero new regressions. The 5-day turnaround from "NOT DONE" to "DONE" was possible because the problem was specific and the solution scope was clear.

### Friction

1. **E2E locator collisions from global mounted side-effects** — CI loop push 1 (f6f49bc) had Playwright fail on `getByRole('status')` because `@dnd-kit`'s `DndLiveRegion-0` (the drag-kit's own live region for keyboard feedback) was on the page and matched the query globally. Push 2 (0e2a5c6) narrowed to `getByRole('status')` within the dialog only; push 3 (b8986db) fixed a second collision where `getByRole('heading', { name: 'Done' })` matched both the inline status message and the Kanban column heading "Done", requiring the locator to be narrowed to `getByRole('heading', { name: 'Done' })` with a role check. **Cost signal:** 3 CI rounds, bundle-of-1-line fixes, but the root cause persists — global side-effect mounts (DnD live region, EmptyState, future toast hooks) will keep poisoning page-wide role queries. **Recommendation for /compound:** e2e locator scoping should be a pipeline-level lint or convention rule, not a per-test workaround.

2. **Local verify doesn't run Playwright** — The builder ran `bun run verify` locally (which passed green) and pushed assuming the implementation was complete. CI Playwright then caught 3 failures that verify had missed. The phase 3 → phase 4 loop involved 3 push cycles to fix visual/behavioral correctness issues the builder couldn't see locally. **Cost signal:** trust gap between `verify` (Vitest + type/lint) and CI (Playwright + real browser). **Recommendation for /compound:** `bun run verify` should either include Playwright, or the README should explicitly state "Playwright runs in CI only; local verify does not catch browser-specific failures." Currently ambiguous.

3. **CI loop blocked by selector specificity details** — Each of the 3 pushes required 1-line locator changes that only become visible when Playwright runs. The fixes themselves are trivial (add `role="heading"`, add `scope to dialog`), but the iteration cost was 3 × 5-10 minutes (push, wait for CI, see failure, diagnose, commit fix). The deeper friction is that e2e tests written in a "happy path" mode don't validate selector scope until the page has real content + global side-effects that conflict. **Cost signal:** e2e tests that pass locally but fail on CI are underspecified initially.

### Cost signals (where time/tokens went)

1. **Architecture R2 CRITICAL fixes** — The missed protected-test contract (`COLUMN_TO_STATE`) and the non-existent `useToast` hook consumed ~60% of architecture critique scope. Both were discoverable failures (static analysis: grep for imports, read test file; static source check: grep for `useToast`). Once identified, the fixes were editorial (add rows to tables, inline feedback region instead of new hook). **Cost:** low in tokens, high in review cycles (R1 fail → R2 pass). **Pattern:** two "did you check the codebase" failure modes that could be caught by a lint rule (unused exports, missing imports).

2. **Focus management implementation** — Implementing focus trap + initial focus + restore-on-close + 4 regression tests took the bulk of Phase 4 fix work. The task itself is standard React (snapshot `activeElement`, wrap Tab, restore in cleanup), but the test cases required careful timing (async focus assertions with `requestAnimationFrame`-deferred behavior). **Cost:** medium tokens, clear acceptance criteria from the review, no ambiguity. **Pattern:** design-promised behavior (focus trap) that was skipped in the builder's first pass; the spec was clear but the builder didn't read it.

3. **CI Playwright iteration** — 3 push cycles × (wait 5 min for CI + 2 min diagnosis + 1 min fix + 1 min commit + 1 min push) = ~50 min elapsed time, <5 min actual code work. The selector collisions are real bugs (locators are too broad), but the latency is organizational (CI pipeline round-trip time). **Cost:** high in elapsed time, low in token spend, bounded by infrastructure. **Pattern:** "local green" → "CI red" feedback loop is inherently slow for visual/DOM tests.

### Pipeline gaps observed

1. **e2e locator scoping lint is missing** — `getByRole('status')` queries collide with global mounted elements (DnD live regions, future toast containers). The pattern is: a new component adds a `role="status"` or `role="alert"` in response to a spec, and immediately existing e2e tests that use the same role break. **Evidence:** L15 added `role="status"` for inline feedback; the Canvas draggable's `DndLiveRegion-0` already mounted the same role; conflict. **Gap:** no lint rule or e2e convention enforces scoping queries to a container (e.g., `page.locator('[role="dialog"]').getByRole('status')`) rather than global (e.g., `page.getByRole('status')`). **Recommendation:** add a Biome/ESLint rule that warns on unscoped Playwright locators in e2e files, or document a mandatory convention in ETHOS.md.

2. **CI Playwright failures are not surfaced until CI runs** — Local `bun run verify` (Vitest + lint) is green; Playwright is CI-only. The result: "I pushed thinking I was green." Three times. **Evidence:** phase 3 builder ran `verify`, saw green, pushed. Phase 4 CI caught Playwright failures. Loop: push → wait 5 min → fail → fix → repeat 3×. **Gap:** `bun run verify` script is ambiguous about what it covers. **Recommendation:** either (a) include Playwright in `verify`, or (b) update CLAUDE.md to state explicitly "Playwright is CI-only; verify does not catch browser-specific failures." Current state: unclear.

3. **Protected-test removal is not caught automatically** — `COLUMN_TO_STATE` export removal would have broken `WorkTeam.test.tsx:73-90` at module load time, but the builder didn't catch it before pushing. **Evidence:** architecture-critique R1 identified it; builder fixed it in R2 as an editorial change (add rows to plan tables, delete the test block). **Gap:** no pre-push lint or test hook that validates "exports are only deleted if their consumers are also deleted" or "test imports are valid." **Recommendation:** a simple `tsc` --noEmit run on the test files would have caught the missing export. This is already in `bun run check`; the builder didn't run it locally before push 1 (push 1 was after architecture-critique R2, so the test deletion wasn't yet in the code; the test deletion was added during phase 3).

4. **E2E test step coverage vs. AC wording** — The AC explicitly says "message appears in the task's thread" (visible rendering). The e2e test `L15-task-request.spec.ts:202-263` proves the message POST succeeds (network interception) but doesn't navigate to the Conversations view to visually assert the message renders. **Evidence:** Review R2 classified this as "CLOSED (with documented constraint)" — the POST interception is sufficient because `ConversationsChat` is still static-mocked in L15, and the rendering contract is deferred to L18. **Gap:** the literal AC (message appears visually) is not 100% proven; the test proves the intent (POST succeeds on the right thread). **Pattern:** AC wording ("appears in the task's thread") is ambiguous between "POST succeeds on the thread" and "message renders visibly." **Recommendation:** future AC wording should distinguish "message is posted" from "message renders" explicitly.

### Concept / domain notes

1. **Request is a plain message, not a new type** — The concept phase settled that "Request" is a convention on top of the existing `plain` message type, not a new `MessageType` or schema field. This avoided ripple changes across `MESSAGE_TYPES` enum (closed per L1), the rails, verdicts, and head-collapse logic. **Evidence:** concept §Probe-1 explicitly enumerated the sites that would ripple if Request were a type; zero ripple because it's plain. **Signal:** when a new feature feels like it needs a new noun, the concept phase should probe whether it's actually a convention on an existing noun. Saves schema / route / type churn.

2. **Idempotency contract inherited cleanly** — The concept settled that double-clicks are handled by L1's existing idempotency contract (threadId, senderId, clientKey) → dedup. The architecture and tests relied on this without adding new logic. **Evidence:** `task-threads.service.test.ts:164-187` verifies retry with same clientKey; no new code needed. **Signal:** when reusing an existing endpoint, dig into its contracts first; they may already solve your problem.

3. **Task ↔ Thread resolution is N+1 for now** — The architecture acknowledged that every Sheet open issues a fresh GET `/api/threads?host_kind=task`. No caching. This is documented as lore (architecture §C lore note). **Evidence:** `L15` does not implement bet-detail-style preload; it accepts 1 round-trip per open as acceptable. **Signal:** explicit acceptance of a sub-optimal design for now (N+1) unlocks the feature to ship. Future optimization (L18 + caching layer) is clear.

### Patterns to feed /compound (3+ recurrences worth flagging)

1. **E2E selector scoping — 3 occurrences:** (a) L15 `getByRole('status')` vs DnD-Kit `DndLiveRegion-0` (push 1), (b) L15 `getByRole('heading', { name: 'Done' })` vs column heading (push 3), (c) implicit: any future `role="alert"` or `role="toast"` component will collide with global toast containers. **Recommendation:** add a Biome e2e lint rule or document mandatory scoping convention. Candidate ID: CC-###-e2e-locator-scoping.

2. **Protected-test removal without audit trail — 2+ occurrences:** (a) L15 `WorkTeam.test.tsx:73-90` COLUMN_TO_STATE contract (caught by architecture-critique, not by lint), (b) implicit in L4+ work. **Recommendation:** either auto-delete orphaned tests (via a pre-push hook) or require explicit "protected tests retired" section in the plan. Existing ID: CC-008.

3. **Local verify ≠ CI verification — 3+ occurrences:** (a) L15 phase 3 push 1 (verify green, Playwright red), (b) any prior workpackage that pushed locally-verified code, (c) implicit: every builder. **Recommendation:** either fold Playwright into `bun run verify`, or add explicit CLAUDE.md notice that verify is incomplete. Existing ID: likely CC-### (verify-scope or ci-local-gap).

## Summary

L15 delivered all 5 acceptance criteria: drag is gone from Kanban, request affordance is in place, Canvas drag is untouched, 36 Vitest + 4 e2e tests pass, and `bun run check/lint/test` is green. The run was structured (5 phases, 2 critiques, 2 review rounds), and the pipeline caught problems at the right gates: architecture R1 caught the missed protected test and non-existent hook; review R1 caught focus management gaps; CI caught selector collisions. The three CI loops were painful but not catastrophic. The three main cost drivers were (1) Architecture critique R1→R2 rework from discoverable static issues, (2) Focus management implementation in review R2 (spec was clear, builder skipped the section initially), and (3) Playwright round-trip latency on selector scoping. No blockers remain; the feature ships. The retro log feeds /compound to identify whether e2e scoping, protected-test removal, and verify scope are systemic issues across 3+ workpackages.
