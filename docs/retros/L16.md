Pitch parsing is deterministic; block ids are stable across re-parses and edits. Runtime data flows exclusively through the `useBet` API hook (no MOCK_BETS fallback). Fixture strings were isolated to `__fixtures__/`, with an ESLint rule enforcing the boundary. ## What went well

1. **Design phase compression — one variant, tight scope.** The design brief was clear (replace `<pre>` with Block primitive, keep markdown on-disk). The design space was naturally narrow (no chrome, no drag, no per-block actions). This allowed the designer to ship concept + design + architecture critique in a single pass without variant exploration, saving 2–3 phase-dispatch cycles. Signal: when the novelty is narrow (consumer of existing primitives, not a new primitive), expect faster convergence.

2. **Reviewer flagged fixtures-isolation correctly.** Architecture R1 caught that the substring-grep test was theatrical (wouldn't catch renames or aliased imports). The fix (ESLint `no-restricted-imports` rule) enforced the invariant structurally at lint time, not through a fragile substring scan. This became a model for future workpackages: structural enforcement beats behavioral tests for boundary rules. Evidence: `eslint.config.js` rule §F; `no-restricted-imports` blocks are now a pattern the team can reuse.

3. **Isolated each design concern cleanly.** The distinction between "render fidelity" (case 1: no `#` symbols visible in the DOM) and "round-trip losslessness" (case 2: pure `deriveBlocks` structural assertion) prevented test duplication and caught the right layer (unit vs. integration). Fixture isolation (ESLint rule) + runtime data path (positive `useBet` test + negative module boundary) gave the reviewer a complete picture. No AC was over-tested or under-tested.

## What went badly

1. **Synthesis e2e regression not caught until CI.** The `useBet` hook changed the WorkBet page to fetch real `/api/bets/:id` data at runtime (no fallback). The synthesis e2e suite (in `packages/web/e2e/synthesis.spec.ts`, outside L16's scope) was mocking the page at a higher level and didn't account for the new fetch. CI caught it; the builder had to push a second commit to mock `/api/bets` in the synthesis suite. **Cost:** 1 CI round-trip, ~5 min elapsed, 1 extra commit. Root cause: the workpackage AC didn't explicitly say "update synthesis e2e mocks" — it was an implicit ripple from removing the runtime fallback. Signal: when a story removes a fallback (mock data), the ripple sites (synthesis, integration e2e) should be enumerated in the architecture or flagged as a pre-push checklist. **Pattern candidate:** `CC-016` (runtime fallback removal ripples).

2. **Two designer revisions with identical symptom, different root.** Commits 1a64dc4 and e9da55a both pushed reviewer-fix recommendations (fixtures-isolation test, `useBet` status, `overrideBet` naming). The issue: after 1a64dc4 was pushed, the designer was notified via SendMessage to apply fixes from R1, but the message didn't reliably resume the designer's session (the agent had already moved to idle state). A second agent was spawned for e9da55a, duplicating the work. **Cost:** 1 extra commit, confusion in the log. **Root cause:** pipeline orchestration assumes SendMessage to an idle/finished agent will resume that agent; in practice, agent session lifecycle is not guaranteed. **Pattern candidate:** `CC-017` (SendMessage to finished agent doesn't reliably resume — spawn fresh agent for revision passes).

3. **ESLint rule is powerful but adds cognitive overhead.** The `no-restricted-imports` rule correctly enforces the `__fixtures__/` boundary, but builders/reviewers now need to understand the rule's scope (ignores patterns for stories + tests + fixtures dir itself, otherwise blocks). If a future builder tries to import a type from `__fixtures__/`, the error message says "Production code must not import from __fixtures__/" — true, but the builder may not immediately realize types are allowed if defined elsewhere. **Mitigation:** architecture doc already handles this (§F "Type-only imports" + §H "Type location"), but a JSDoc comment at the ESLint rule itself would help. Not a blocker; more of a "invest in lore" note.

## Patterns observed

Checking against L15's `docs/retros/L15.md` and proposing new codes:

1. **E2E tests hit unfixed ripple sites when a runtime fallback is removed.** L15 had selector collisions (3 rounds); L16 had a synthesis e2e mock missing (1 round). Both stem from the same root: changes to the runtime data path or component shape ripple into e2e suites that are outside the workpackage scope. **Existing code:** likely a variant of CC-008 (protected-test removal). **Recommendation:** propose `CC-016-synthesis-ripple` — when a story changes how a page fetches data or removes a fallback, the architecture should enumerate all e2e suites that mock that page/endpoint and flag them for review. Assign to /compound to track.

2. **SendMessage to an idle/finished agent doesn't reliably resume — spawn fresh agents for revision passes.** L15 didn't have this pattern (revisions were within a single agent dispatch). L16 hit it twice (1a64dc4 + e9da55a pushing the same fixes because the designer session wasn't resumed). **Recommendation:** propose `CC-017-sendmessage-resume-gap` — agent orchestration should not rely on SendMessage to wake a finished agent; instead, spawn a fresh agent for each revision pass to ensure deterministic execution. This is a process/pipeline concern, not a code concern. Assign to /compound + `/pipeline` skill for future workpackages.

3. **ESLint structural-boundary rules are superior to behavioral tests for boundary enforcement.** L15 deferred protected-test audits to the review phase (manual scanning). L16 enforced fixtures-isolation at lint time (structural rule). The rule catches every violation regardless of the specific symbols, and it runs on every commit (zero friction, high reliability). **Existing code:** likely CC-008 or a new variant. **Recommendation:** document this as a pattern in `/compound` — prefer `ESLint no-restricted-imports` over substring tests for enforcing architectural boundaries. Cite evidence from L16 (§F rule vs. dropped substring-grep test).
