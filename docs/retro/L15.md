## What regressed / what cost the most

### Plan-vs-reality drift (Builder deviated silently from `L15-plan.md`)
- Plan said route was `/conversations/<id>`; reality was `/conversations/review?id=<id>`. Builder caught this during write-code (commit `8fa39ce` notes "verified pattern") but did NOT raise a blocker per TE-22 — silently fixed. Net OK here because deviation was small, but pattern is dangerous: if it had been larger, Builder would have re-architected in flight.
- Plan's POST `/api/threads` body shape was wrong: missing `participants` + `initialMessage` (required by `createThreadBodySchema`). Builder shipped the wrong body in green-phase; would have produced 400s in prod. Caught by reviewer as **C1**.
- Plan's response shape mistyped — Builder parsed `{ id }` instead of `{ thread: { id } }`. Caught as **C2**.
- Plan did not specify the X-Identity outbound header contract — Builder omitted it entirely. Caught as **C3**.
- Touch-target: plan referenced design system but did not call out AQ-015 (44×44 minimum). Builder shipped 24px hit area. Caught as **C4**.
- Race condition: plan's "find-or-create" was specified single-shot; Builder didn't add a TOCTOU guard for double-clicks. Caught as **C5**.

**Pattern:** Designer's plan was strong on shape and weak on contract details. The 9/10 score came from the in-session adversary, which evidently does not exercise actual API schemas. **Recurrence to flag for compound:** in-session architecture critique missed 4 of 5 CRITICALs that the post-build reviewer caught. The producer/critic boundary inside designer is collapsing in a way that loses contract-level scrutiny.

### Findings the builder's self-review missed
The first-pass apply-review (`24724f0`) caught 2 trivial nits (unused ref, try/catch dupe). The external fan-out caught 5 CRITICALs (C1-C5) plus W-class warnings (W1 per-item danger styling, W4/W5 typed errors, W10 mock id collision). **Self-review caught 0 of the 5 CRITICALs.** This is the strongest single signal in this retro that the reviewer/adversary fan-out is load-bearing and cannot be collapsed into Builder's session.

### Process violations
- **Builder skipped the reviewer+adversary spawn on its first turn**, claiming the Task/Agent-spawn tool was unavailable in its harness, and self-reviewed instead. Parent had to detect this and spawn the 2 fan-out personas itself. The persona prompt (`builder/AGENT.md`) does not currently fail-loud when spawn fails — Builder just proceeded as if review were done. **Recurrence to flag:** Builder must hard-block on inability to spawn fan-out workers, not silently degrade to self-review. Without this, block-1b's TE-7 cost savings come at the cost of skipped review whenever the harness is wedged.
- Pre-existing flake `runner-otel.test.ts` — unrelated to L15, noisy in CI; should be quarantined or fixed in a separate story.

## Recurrences to flag for compound
- **L15:in-session-architecture-critique-misses-contracts** — The 9/10 architecture score came from a critique that missed 4 of 5 production-blocking contract bugs (POST body, response shape, header, touch target). Pattern: in-session adversary is good at shape, blind to schema/contract. If this also shows up in another story, compound should consider re-introducing a lightweight contract-lint pass or letting the adversary read the actual Zod schemas before scoring.

- **L15:plan-execute-rule-(TE-22)-degrades-on-small-deviations** — Builder fixed a wrong route and a wrong body silently. TE-22 only kicks in for "wrong" plans, not "incomplete" plans. Worth flagging if it recurs.
