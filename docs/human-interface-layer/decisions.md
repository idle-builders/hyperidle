# Decisions

Settled decisions for the human interface layer. Each entry is the decision plus the code that carries it. Architecture-wide decisions live in [architecture/decisions.md](../architecture/decisions.md).

- **Desktop shell:** Electron, server embedded in the main process. Desktop is the primary form factor. Delivery and mobile posture (web from mobile browsers, no native app, no offline) is owned by [architecture/system-overview.md](../architecture/system-overview.md).
- **UI stack:** Tailwind CSS + DaisyUI + Hearth theme (light/dark/system). Behavior gaps filled by `focus-trap-react` and `@floating-ui/dom`. Theme and token authority: [ui-design/foundation.md](../ui-design/foundation.md).
- **Bet creation:** symbolic UI — standard React components with a hard capacity cap. Humans create bets via the `WorkBetCreate` page form, not drag-and-drop.
- **Navigation model:** view switching + per-view sub-navigation + main content pane. Breadcrumbs within views, not across. Shell layout structure is owned by [information-architecture/app-shell-always-present.md](../information-architecture/app-shell-always-present.md).
- **Thread primitive:** one Thread model with typed messages — `plain | review | questionnaire | verdict` (`framework/domain-model/src/thread.ts`). No separate "review threads" vs "chat threads"; the distinction is derived from message content. See [thread-primitive.md](thread-primitive.md).
- **Assistant:** just another agent identity-wise — it communicates through normal threads like any teammate — but it has a dedicated surface: the `AssistantOverlay` (opened from the sidebar), plus attach affordances (`AssistantAttachButton`).
- **Human-initiated conversations:** humans can create threads with agents and dial into live sessions.
- **Notifications:** channel set decided and shipped (AF8) — `console | ntfy | smtp` (`layers/core-api/notifications/src/install.ts`). Primitive semantics: [notification-primitive.md](notification-primitive.md).
- **Knowledge view model:** catalogue with topic/node structure, not page tree. Seven scopes — `factory | product | practice | team | bet | task | user` (`framework/domain-model/src/types.ts`). Humans author knowledge at any scope; threads attach to knowledge items for discussion. Store semantics: [knowledge-architecture/the-canonical-store.md](../knowledge-architecture/the-canonical-store.md).
- **Knowledge view:** relevance signals on every item (`attentionScore`, `relevanceScore`, `citationCount`, `lastCitedAt` — `schema.ts`; owned by [knowledge-architecture/relevance-and-attention.md](../knowledge-architecture/relevance-and-attention.md)). Two tabs: Triage (draft) and Curated (active).
- **Review artifact embeds:** the six fundamental `ARTIFACT_KINDS` — `text | code | image | data | html | url` (`framework/domain-model/src/kinds/registry.ts`) — same vocabulary an Artifact is created with. The retired five-value `ARTIFACT_VIEW_SHAPES` enum (`text_diff | content_preview | visual_comparison | action_summary | data_metrics`) is deleted, not migrated. These are embed layouts inside review messages, not standalone renderer components; the contract is owned by [process-layer/artifact-primitive.md](../process-layer/artifact-primitive.md). Simple artifacts render inline in the thread; complex artifacts promote to a companion pane (conversation left, artifact right).
- **Task interaction:** tasks are agent-owned. Humans do not drag or move tasks; state changes are requested via thread conversations. Bet-level actions show consequence previews.
- **Settings:** overlay pattern. Twelve sections (`layers/core-ui/src/settings/`): Profile, Org Chart, Notifications, Appearance, Backend, Agents, Agent behavior, Connections, Credentials, Filesystems, Agent backends, Worker.
- **Setup:** full-page `SetupFlow` guides first-run, with contextual hints for first-time interactions.
