Webhook signing: how we verify Stripe events

1 F

When Stripe POSTs to /api/webhooks/stripe, the request includes a Stripe-Signature header. Verifying this header is not optional — without it, anyone can forge events and mark invoices paid.

The verification protocol

We use Stripe's official constructEvent from the SDK. Three rules:

  1. The signing secret comes from .env.production under STRIPE_WEBHOOK_SECRET. Never inline it.
3 B P B
  1. The raw request body is required — do not parse JSON before verification.
  1. Reject any event older than five minutes (replay protection).
ts 
const event = stripe.webhooks.constructEvent(
  rawBody,
  request.headers.get('stripe-signature'),
  process.env.STRIPE_WEBHOOK_SECRET,
  { tolerance: 300 /* seconds — replay window for redelivered payment_intent.succeeded events */ },
);

Anti-patterns we caught in review

  • Trusting the parsed body. A Builder once parsed JSON in middleware before signature verification — the verification then fails because the raw bytes have been mutated.
  • Skipping the timestamp check. A replay window of "any age" lets an attacker resend old events.
1 P
Last incident (Q3): a missed timestamp check let a redelivered payment_intent.succeeded mark an invoice paid twice. Now part of our default checklist.
