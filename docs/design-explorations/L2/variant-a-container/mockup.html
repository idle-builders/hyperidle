Reduce intake review latency

Today our intake queue waits a median of 11.3 hours between submission and first review. We see this happening when the rotating reviewer switches contexts mid-day — an effect well documented in Beck & Andres (2019) and reproducible in our own telemetry. The remedy is mechanical: route by load, not by name. The hot path should run scheduler.assignNext() instead of the manual handoff channel, _and_ we should stop hard-coding reviewer slots.

2

How we know it’s the bottleneck

We instrumented every intake touchpoint for two weeks. The data is unambiguous — two thirds of total wall-clock time sits between “submitted” and “first eyeballs”, and the other third is split across review work proper.

Approach

  • Replace the manual handoff with scheduler.assignNext().
    • Skip reviewers above their concurrent-load cap.
      • Cap defaults to 3, configurable per product.
    • Prefer reviewers who have context on the bet’s product.
  • Drop the rotating-reviewer channel entirely.
  • Add a p95 latency alert at 12h.
  1. Land the scheduler hook behind a flag.
  2. Dual-write to old + new for one week.
  3. Cut the old path; remove the channel.

“We should stop talking about who reviews what and let the system pick.” — founder note, intake retro, 2026-04-12.

// scheduler.ts
export async function assignNext(bet: Bet): Promise<Reviewer> {
  const eligible = await reviewers.where({
    productId: bet.productId,
    activeLoad: { lt: REVIEWER_LOAD_CAP },
  });
  if (eligible.length === 0) {
    return reviewers.fallback(bet.productId);
  }
  return eligible.sort(byContextScore(bet))[0];
}

const REVIEWER_LOAD_CAP = 3;

Load-balanced review routing

When a queue has multiple eligible workers and round-robin produces uneven wait times, route by current active load rather than by rotation. The routing function should be deterministic given the same input set so that re-runs of the planner produce the same assignment.

When to apply

  • The queue produces variance >2x between fastest and slowest worker.
  • Workers have a measurable concurrent-load signal.
    • Open tasks, pending reviews, in-flight calls, etc.
  • Round-robin is the current default.
