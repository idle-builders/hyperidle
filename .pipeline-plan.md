## 3. Schema — `recovery_audit` and `factory_state`

```ts
recoveryAudit = sqliteTable("recovery_audit", {
  id:        text("id").primaryKey(),                       // ulid
  actorId:   text("actor_id").notNull().references(()=>actors.id,{onDelete:"restrict"}),
  verb:      text("verb").notNull(),                        // RecoveryVerb
  reason:    text("reason").notNull(),                      // ≤500 chars (CHECK)
  targetKind:text("target_kind").notNull(),                 // 'factory'|'thread'|'session'
  targetId:  text("target_id").notNull(),                   // 'factory' for global
  at:        text("at").notNull(),                          // ISO
  outcome:   text("outcome").notNull(),                     // 'pending'|'succeeded'|'partially'|'failed'
  meta:      text("meta"),                                  // JSON: {priorState, affected:{sessions:[…]}}
}, (t)=>[
  index("recovery_audit_actor_idx").on(t.actorId),
  index("recovery_audit_target_idx").on(t.targetKind, t.targetId),
  index("recovery_audit_at_desc_idx").on(t.at),
]);

factoryState = sqliteTable("factory_state", {
  id:           text("id").primaryKey(),         // singleton 'factory'
  paused:       integer("paused",{mode:"boolean"}).notNull().default(false),
  pausedBy:     text("paused_by"),               // actor id
  pausedAt:     text("paused_at"),
  pausedReason: text("paused_reason"),
});

// sessions: ADD COLUMN pause_checkpoint text  -- JSON snapshot for resume
```

CHECK constraint on `reason` length is enforced at the API layer (Zod `max(500)`); SQLite CHECK omitted because `length()` semantics differ from char count for multibyte. ⚠️ UNVERIFIED: Drizzle SQLite CHECK on `length()` not used here — Zod is the single gate.

## 4. API Contract

All routes require `X-API-Key` (auth middleware) + `X-Actor-Id` (resolved by `actor-context.ts`). Bodies are Zod `.strict()`. Identity NEVER comes from body.

| Route | Body | 200 | 400 | 401 | 403 | 409 | 410 | 423 |
|---|---|---|---|---|---|---|---|---|
| `POST /api/factory/pause` | `{reason: string≤500}` | `{state:'paused', pausedAt, audit_id, affected:{sessions:N, tasks:M}}` | invalid body / empty reason | no actor | n/a | already paused → `{error:'already_paused'}` | n/a | n/a |
| `POST /api/factory/resume` | `{reason: string≤500}` | `{state:'running', resumedAt, audit_id}` | invalid body | no actor | n/a | not paused → 409 `not_paused` | n/a | n/a |
| `GET /api/factory/state` | – | `{paused, pausedBy, pausedAt, reason}` | – | – | – | – | – | – |
| `POST /api/threads/:id/verdict/rollback` | `{reason: string≤500}` | `{audit_id, outcome:'succeeded'\|'partially'\|'failed', detail?}` | invalid / empty | no actor | actor_mismatch (cross-founder) | `agent_already_acted` (mirrors L4) | `not_reversible` (placeholder until L9: returns 410 `not_reversible_yet` only when artifact metadata explicitly says false; until L9 ships always allow) | factory paused (no rollback while paused; surface 423 to keep semantics clean) |
| `POST /api/sessions/:id/pause` | `{reason: string≤500}` | `{state:'paused', checkpointAt}` | invalid body | no actor | n/a | already paused / terminal state | session not found → 404 | – |
| `POST /api/sessions/:id/resume` | `{reason: string≤500}` | `{state:'running'}` | invalid | no actor | n/a | not paused / terminal | – | factory still paused → 423 |

Error envelope: `{error, code}` per existing `ApiErrorResponse`.

## 6. Confirmation Pattern

`KillSwitchDialog` props: `{verb, target, blastRadius, onConfirm, onCancel, mode: 'type_name'|'press_hold'}`.

- **Blast-radius preview** rendered top: `"This will pause N sessions across M products"` (factory) / `"This will rollback verdict on <thread title>"` / `"This will pause session <id> on agent <name>"`. Computed server-side via `GET /api/factory/blast-radius` (cheap aggregate) for factory; client-derived for session/rollback.
- **Rationale field** — `<textarea maxLength={500}>`, required, live counter `N/500`.
- **Confirm gate** (one-of):
  - *Type name*: input must equal target name (factory name from `/api/me`'s factory, or thread title slug). Case-insensitive match. Submit disabled until match.
  - *Press-and-hold*: button uses `pointerdown`/`pointerup` + `requestAnimationFrame` ramp; fires `onConfirm` only after 1500ms continuous hold. Releasing early resets the ring. Honors `prefers-reduced-motion` by replacing the ring with a numeric countdown ("Hold 1.5s… 1.2…").
- **Submit** — POSTs the corresponding endpoint with `{reason}`. Disabled while in-flight. Renders 4xx error inline.
- Mode pref read from `appearance.killSwitchConfirmMode` in SettingsData (added in L7).
- **Resume reuses the same dialog** with `verb='resume'`. Rationale OPTIONAL for resume (spec only mandates rationale for kill / rollback / mid-session-stop); the rationale field still renders for traceability but submit is enabled with empty text. Confirmation gate (type-name or press-hold) IS still required — spec's "explicit confirm."
- Press-hold button ≥44×44 CSS px (AQ-015); rationale textarea uses `--density-text` ≥16px on mobile (AQ-005).

## 8. Blast Radius (Code Touchpoints That Must Consult Kill State)

Routes that mutate or trigger NEW agent work must check `factoryState.paused` and refuse with **423 Locked** while paused, EXCEPT resume verbs, the kill verb itself, pure reads, and reversal verbs (which act on existing state and must remain available so the founder can clean up):

- `POST /api/threads/:id/verdict` (commit verdict — dispatches agent work) — BLOCKED
- `POST /api/threads/:id/verdict/undo` (L4) — ALLOWED (reverses a row, no new agent work)
- `POST /api/threads/:id/verdict/rollback` (L7) — ALLOWED (cleanup verb; the whole point of pause is to clean up bad output)
- `POST /api/sessions` create / `POST /api/sessions/:id/start` — BLOCKED
- `POST /api/tasks` create / state transitions to `in_progress` — BLOCKED
- `POST /api/bets` activate — BLOCKED
- `POST /api/sessions/:id/pause` — ALLOWED (idempotent under paused-factory)
- BullMQ scheduler — guard at job-pickup time, not at enqueue (queued tasks remain queued and replay on resume).

Adversary fix: §4 row for rollback removes the 423 column — rollback is allowed while paused.

`factory-paused-guard.ts` is a Hono middleware used as opt-in (per route group) — NOT global, because reads (`GET /api/conversations`, `/api/me`, `/api/factory/state`) must keep working.

UI components consulting state via `useFactoryState`:
- `AppShell` (banner)
- `ReviewHeader` / verdict bar (disable Approve/Reject buttons, show "Factory paused")
- `WorkBet`, `WorkTeam` (Pause buttons hide Resume of individual sessions while factory paused — factory resume must run first)
- `MobileTabBar` verdict surface (L5) — same disable

## 9. Risk Register

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| **R1: Pause not durable across server restart** — in-memory flag would let agents resume after a crash exactly when the founder least expects it | Med | High | Source of truth is `factory_state` row in DB; middleware re-reads (or 30s-cached with invalidate-on-write); BullMQ workers also poll the row before picking jobs. Test: restart server mid-pause, assert state still paused. |
| **R2: Rollback "best effort" silently lies** — agent runtime can't undo emails / git pushes; user thinks rollback happened | Med | High | Service returns explicit `{outcome:'failed', detail}` and writes that into `recovery_audit.outcome`. UI surfaces failure in red; never green-toast on `failed`. Spec already mandates this. |
| **R3: Cross-founder kill / actor spoofing** — body-supplied actorId would let one founder attribute kill to the other | Low | High | Identity exclusively from `X-Actor-Id` header (mirrors L4 security pattern). Zod `.strict()` rejects body `actorId`. Test: PR-time security review + integration test asserting body actorId → 400. |

### CONFUSION: kill vs pause for factory scope
Spec says "kill terminates and discards in-progress work; pause preserves." Yet the factory-wide verb is named "Pause Factory" (kill switch). Two interpretations:

A) **Factory-pause = preserve-and-suspend.** All sessions move to `paused` with checkpoint. Resume continues. ("Kill switch" is colloquial.)
B) **Factory-kill = terminate.** Sessions go to `killed`, work discarded. Mid-session pause is the only "preserve" verb.

Proceeding with **(A)** because (i) spec validation scenario says "all 3 sessions move to `paused` within 2s," (ii) "Pause Factory" is the literal action name in three of three entry points, (iii) discarding work on a global kill is too costly for a UX shipped on day one. The "kill" in "kill switch" is the mechanism (immediate stop), not a destructive lifecycle transition. Flag for human review at /retro.
