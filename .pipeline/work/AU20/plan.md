# AU20 — Redesign every Service as its own product (collapse the export sprawl into a small set of well-structured general interfaces)

Shipped 2026-07-26 on `pipeline/AU20` (review verdict DONE), after the founder rejected an earlier concept gate and later returned the whole work package to pipeline start once. Reopened 2026-08-17 as a destroyer pass. Named deferrals went to AU23; the destroyer pass's remaining rows are carried on AU44.

## What we need

Continuing the simplification AU19 started: collapse the Service layer's exposed surface into a small set of coherent, general interfaces per Service, and justify every Service's existence from product purpose. AU19 measured **1218 exported symbols across 31 Services** (`knowledge` 138, `notifications` 89, `work` 84, `harness-registry` 79). For an MVP tool that number is itself the finding — a bespoke method carved to fit each individual call site. Knip cannot see this: it removes only *dead* code, and a one-caller method is used, not dead, so over-fragmentation of live code has to be read and reasoned about.

Every Service gets a written holistic analysis as its own product across two lenses — **OUTSIDE** (what do I offer/expose) and **INSIDE** (how do I stay evolvable so new features and behaviour changes stay cheap) — plus an existence verdict of standalone / consolidate / dissolve, reasoned from product value and layer position. Consolidating several small Services into one larger one is a first-class outcome. Infra `agent-orchestration` / `agent-execution` Services are platform products whose customers are other Services; they meet the same bar, stated with named internal consumers.

The founder's rules bind every judgment. Usage is an input reasoned *from*, never a verdict and never a mandate for a method per request — "is it called", "owns a table", "has a loop", "clean name for a concept" are not valid keeps. The **scaling test** is the concrete form of the standard: adding dozens more services and hundreds more calls must compose from the existing interfaces, not spawn hundreds more methods. North star — an interface parameterized by intent/filter (`list(filter)`, `transition(from,to)`) is general; a method per intent (`listActiveByTeam`, `listPinnedByHost`, …) fails. A "keep unchanged" verdict is not an exemption and carries the identical justification burden.

Tier is **mvp**, asserted per-plan from `ETHOS.md` §1 because the global `engineering.tier` config was still landing via the open PR #454.

Alongside that, three tier-independent correctness bugs AU19 had already code-verified. Done when every Service has that analysis and a redesigned general API, each independently critiqued by a different agent *before* its reductions apply; the reductions are applied with the suite green and no behavior change; and the three bugs are fixed.

**Out of scope.** A per-method keep/merge/inline/delete rubric decided by call-site count — the explicitly rejected frame. A usage-driven method-per-request API. Judging existence by table ownership or caller count. The `agent-orchestration → core-api` edge graph (that is AU21; shared fixes cross-reference, never double-fix). A from-scratch re-partition of the domain data model beyond what a specific fold entails.

## How it works

`scripts/generate-dependency-graph.ts` was extended — not forked — into a re-runnable per-Service demand package: each Service's exports plus its DI-port-resolved consumers and what each requests, including destructured/aliased receivers. That data informs each analysis; it never judges. Thirty-one planner→reviewer→revise chains ran over it, then the reductions were applied as one commit per increment, each green before the next.

Result: **31 → 23 Services**, 1218 → **412 exports** (23 services / 231 methods / 181 types), a census locked and guarded so later method growth cannot slip in.

The single biggest mechanical win was ruling that **DI-port type re-exports are not product surface** — each Service's `*Ports`/`*Deps`/`*Accessor` mirrors bundle into one `<Service>Deps` wired once at the composition root (58% of `dispatch`'s surface). Parameterized interfaces are typed through a pinned entity→row registry with return types conditional on the discriminant, never a widened union the caller has to re-narrow. Every merge moved tables, ports, reads and writes together atomically, with the ownership guards green.

The merges: `session-requests` absorbed `trigger-resolution` + `lifecycle-projection`, removing two dependency cycles; `run-orchestration` absorbed `session-lifecycle` + `context-assembly` + `capture-writeback` and became `session-runtime`; `harness-registry` absorbed `tool-provider` + `mcp-provider` last, behind a dependency-isolation proof, because their Hono/MCP-SDK runtime deps had to stay out of the remote-worker build or the zero-DB seam breaks. `retention` dissolved into per-schema `reapExpired` sweeps with a generic scheduler at the composition root. `checkAndUnblockDependents` moved from `filesystems` to `work`; practice-meeting to `knowledge`.

`git-export` was the one place method-per-verb was upheld as correct: a generic `git(args)` passthrough was rejected because the typed, whitelisted verbs are the seam that keeps tokens out of argv.

The three bugs: `log_task`'s read-modify-write became an atomic append primitive in `work` mirroring `incrementBetCost`, with a real two-writer concurrency test; the duplicate `getTeamMembersById` read in `cost-cap.ts` was inlined; the duplicate `getUserById` was threaded through the session chain (the two `session-context.ts` hits sit in different functions and were never the duplicate).

The first pass claimed green and was not. A fresh review found five criticals and four warnings and E2E proof was unreliable, so the founder revoked implementation authorization and sent AU20 back to the start. The corrective pass landed five separately reviewed green increments, and their shapes are why the code looks as it does today: the demand-package generator is deterministic (two runs byte-identical); `ServerHandle.dispose()` returns `Promise<void>` and runs a six-phase ordered teardown (bet-decomposition → runtime → app-domain → websocket → http → owned-db) where every phase runs even after a failure, failures surface as one phase-tagged `AggregateError`, the call is idempotent, and injected databases are never closed; harness-registry's MCP entry moved to a `./mcp` subpath so the main bundle carries zero MCP-SDK/Hono/Zod, proven by the esbuild metafile; knowledge retro hypotheses are snapshotted at creation and survive later verdict edits; bootstrap names its nine disposal owners with metadata (the test expecting ten was stale).

Two warnings changed error semantics: notification `writeSecret()` now catches only `MISSING_ROOT_SECRET` and rethrows every other cipher error so no success audit is reached, and the filesystem watcher exposes an observable `config.onError`, tearing down fully before surfacing and rethrowing on setup failure instead of swallowing.

Accepted deferral: real-backend E2E, browser and desktop runtime proof lanes, and desktop smoke (dev-local and packaged-local/shared) are **AU23's**, which is why corrective criteria C3 and C6 are POSTPONED and C5 PARTIAL.

The corrective design pass was deliberately recovery, not redesign — no UI changed. Legacy restoration, a fresh redesign, and a selector-preservation shell were all rejected; the last because keeping obsolete wrapper and test IDs would encode implementation history as product contract. 116 runtime design obligations were handed to AU23 with it.

Reopened 2026-08-17 as a destroyer pass, because the first pass predated the code graph — nothing had been traced to a real door, and the `packages/` → `layers/`+`framework/` restructure killed every path in its analysis. It re-ran as 38 agents, one per service, per framework package, and one for the entry-door surface, tracing every export to a UI, agent-harness or scheduler door against a standing bar: a method survives only if it proves a core value. **1,713 rows, one verdict each, nothing sampled**: 423 delete, 21 plugin, 22 finish, 72 merge, 327 simplify, 848 keep.

Three founder rulings reshaped it and outlive this work package. **(1)** The product runs as a shared backend for a team and an organisation of teams; identity arrives through an OIDC provider, not invitations, and nothing may be judged as though the product had one user — fifteen packages were re-audited on that basis. **(2)** Events are an extension surface: everything that happens emits an event and plugins attach triggers, so "nothing internal subscribes" is never evidence of death and no event type may be deleted for lack of an in-repo listener. **(3)** Knowledge-management ritual leaves core and becomes a plugin — the test is whether something is the machinery of working or a ritual *about* the work.

The corrected premise exposed defects the single-user lens had hidden, none of them the audit's own targets: two direct-message dedupe paths that cannot see each other and fork threads between the same pair; an unscoped conversation list returning every human's direct messages to any caller; approval rates aggregating all humans into one number; ship confirmations addressed to a hardcoded first-human-by-insertion-order; and a proposed-call path hardcoding every call irreversible — the gate-by-default classifier the ethos forbids, inside a feature the product intends to finish.

Two of this work package's own claims were wrong and had been acted upon before being caught: the propagation retry tick is **not** bookkeeping (task-to-bet is a real database transition healed only there, and it survives), and agent completion text already arrives from all four harnesses and is silently dropped, which makes a live session view a missing case arm rather than a feature build.

## How we work on this

The audit contradicts itself in places. The service destroyer and the door destroyer judged the same features differently — the org-edge matrix was convicted as an approval chart while the routes serving the org chart were kept; knowledge merge and split were convicted as unreachable while their doors were marked for the plugin. The delete pass was briefed on the service verdicts alone, which is how three user-facing surfaces were deleted while marked KEEP. Anyone acting on the remaining rows must read **both** sides for a feature before touching it.

The full audit, per-package verdicts, revised verdicts, census and tooling were committed during the pass and removed at ship, because they are working material rather than product. Both cleanup passes were squash-merged, so that commit is **not reachable from `main`**. They are carried on branch `pipeline/AU44` under `.pipeline/work/AU20/destroy/` (110 files) and are also reachable from the tag `au20-audit-evidence`. The branch is the copy to work from; the tag is the backstop. Nothing in this track should assume `main` carries them.

Re-running the tooling: `check-deletions-scoped.ts` resolves each verdict file to a package directory by name, and AU44 dissolved fifteen of those packages. It now silently skips 75 DELETE rows as "no resolvable dir" rather than checking them. Give it a package-to-new-home mapping before trusting its number as a gate.

Two standing constraints found while correcting the run. `knip:production` conflates two questions and diagnoses live test-support modules as unused; it must run as unused-file analysis with normal entry reachability plus a production pass through the `scripts/knip-production-test-files.mjs` preprocessor, and those modules must not be deleted or inlined. And `claude mcp list` health-checks every project and account server before emitting its table — observed at 2.7–5.5s — so the old 5s race inside `inspectClaudeTools` made a configured project identity vanish on unrelated server latency; the command's timeout must allow for that.
